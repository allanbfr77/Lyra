PLANO DE REDESIGN · v1 · Agosto 2026

Transformar o Lyra num produto com
cara de software profissional da Microsoft.

Este documento analisa a interface atual do Lyra Controlador (app Electron de projeção para igrejas) e propõe um redesign completo alinhado ao Fluent Design / Windows 11 — preservando 100% da lógica de negócio. O objetivo é qualidade visual comparável a Explorador de Arquivos, Configurações, PowerToys e Windows Terminal.

Escopo

Controlador (painel do operador). Servidor e Mobile herdam os mesmos tokens depois.

Princípio

Só a camada de apresentação muda. IDs, funções onclick e fluxos permanecem.

Entrega

Este plano + um mockup HTML interativo com temas claro e escuro.

01 Problemas encontrados na interface atual

Análise do controller.html (arquivo único, ~8.300 linhas, CSS e JS embutidos). O app funciona bem, mas a camada visual traz marcas de "sistema interno" em vez de produto.

Nota positiva

A arquitetura já usa variáveis CSS (--bg, --surface, --accent…) e color-mix(), e já suporta tema escuro via html.dark. Isso torna o redesign viável trocando apenas os tokens e o CSS dos componentes, sem tocar no JS.

02 O que deve mudar

Identidade visual

Migrar da paleta ouro/marrom para a neutra do Windows 11 (Mica + cinzas), com azul de acento para controlos e o ouro Lyra reservado à marca (logo, destaque de projeção ativa).

Tipografia

Adotar Segoe UI Variable (fallback Segoe UI) e o ramp Fluent. Abolir CAIXA ALTA em botões; usar peso semibold para hierarquia.

Navegação

Substituir o dock de ícones redondos por uma NavigationView lateral (rail) com ícone + rótulo, e uma CommandBar superior contextual.

Densidade e layout

Grade de 4px, respiro consistente, e toolbar contextual — só as ações relevantes ao estado aparecem, em vez de dezenas de botões escondidos.

Componentes

Recriar todo o kit (botões, inputs, selects, switches, listas, árvores, tabelas, menus, dialogs, toasts…) a partir de tokens únicos.

Feedback

Adicionar toasts, progress, skeletons, spinners, empty/error states e indicadores de conexão/sincronização padronizados.

03 Justificativa de cada mudança

MudançaPor quê
Neutros + azul de acentoO ouro/marrom sinaliza "tema personalizado"; a base neutra do Windows 11 é o que o olho reconhece como "app do sistema". O azul concentra a atenção nas ações, e o ouro vira assinatura da marca em vez de cor de fundo.
Segoe UI VariableÉ a fonte nativa do Windows 11. Usá-la (com o ramp oficial) é o fator isolado que mais aproxima o app do visual Microsoft. Reduz corpo de 17px → 14px, ganhando densidade sem perder legibilidade.
Fim da CAIXA ALTABotões em maiúsculas são mais lentos de ler e destoam de Configurações/Explorador. Sentence case + semibold dá a mesma ênfase com aspecto mais limpo.
NavigationView lateralPadrão Fluent para apps com múltiplos modos. Ícone + rótulo elimina a dependência de tooltips e reduz cliques (modo sempre visível).
Toolbar contextualMostrar só o que é acionável no estado atual reduz a poluição e o erro. Segue o CommandBar de Fluent (ações primárias à vista, secundárias em overflow "⋯").
Tokens únicos + elevaçãoUm sistema de camadas (Base/Card/Flyout/Dialog) e sombras padronizadas dá coerência e facilita manutenção — trocar um token propaga a todo o app.
Estados e foco visíveisHover/pressed/selected/focus consistentes melhoram usabilidade e acessibilidade (foco de teclado é requisito para operar ao vivo, sem mouse).
Ícones FluentUma família única (Fluent UI System Icons / Segoe Fluent Icons) elimina o mosaico de ícones atuais e garante alinhamento óptico.

04 Referências ao Fluent Design & Windows 11

O redesign segue os cinco fundamentos do Fluent (Light, Depth, Motion, Material, Scale) traduzidos para um app de projeção:

Material — Mica & camadas

Fundo base em tom Mica (#F3F3F3 / #202020); conteúdo em camadas sólidas com bordas sutis. Superfícies "acrylic" (translúcidas) reservadas a flyouts e menus.

Depth — elevação

Quatro níveis: Base → Card (sombra leve) → Flyout (8/16) → Dialog (32/64). Nada de sombras duras espalhadas.

Motion — conexão

Transições curtas (100–250ms) com easing padrão; page-transition por fade+slide sutil; expandir/colapsar suave. Sem exageros — respeita prefers-reduced-motion.

Scale — do HD ao 4K

Layout fluido com clamp(), tipografia em px lógicos e alvos de toque ≥ 32px. Painéis proporcionais, não fixos.

Apps de referência

Configurações

NavigationView, cards de settings, agrupamento por seções.

Explorador

Rail + CommandBar, TreeView, seleção e context menu.

PowerToys

Cards de configuração, toggles, InfoBar, densidade equilibrada.

Windows Terminal

Tema claro/escuro, abas, paleta de acento, tipografia mono.

Regras de uso

  • Botões: Body (14px), sentence case — nunca CAIXA ALTA. Ex.: "Editar letra", não "EDITAR LETRA".
  • Títulos de tela: Title 28/600. Seções: Subtitle 20/600.
  • Listas e menus: Body 14/400; item selecionado em Body Strong.
  • Números tabulares (versículos, tempos, zoom): font-variant-numeric: tabular-nums.

09 Biblioteca de ícones recomendada

Recomendada — Fluent UI System Icons

Família open-source da Microsoft (MIT), variantes Regular e Filled, otimizada para 16/20/24px. Cobre navegação, mídia, edição e status. Disponível como SVG e webfont.

github.com/microsoft/fluentui-system-icons

Alternativa — Segoe Fluent Icons

Fonte de ícones nativa do Windows 11 (a mesma do sistema). Máxima fidelidade visual, mas licença restrita a apps Windows — usar apenas no build desktop.

Padronização

  • Tamanho base 20px na UI (16px em listas densas), traço/óptica consistentes.
  • Regular para ações; Filled para estado ativo/selecionado.
  • Remover os ícones redondos personalizados atuais e o mosaico de glifos (☾, ●, ◀ ▶) por equivalentes Fluent.

11 Roadmap de implementação por etapas

Incremental e de baixo risco: a lógica não muda; cada etapa é testável isoladamente. O suporte a variáveis CSS já existente permite começar só pela troca de tokens.

Etapa 0~0,5 dia
Fundação de tokens. Substituir o bloco :root e html.dark pelos novos tokens (cor, tipo, espaçamento, raio, sombra, animação). Ganho visual imediato sem tocar em HTML/JS.
Etapa 1~1 dia
Tipografia. Carregar Segoe UI Variable (fallback), aplicar o ramp, remover CAIXA ALTA dos botões, ajustar tamanhos e pesos.
Etapa 2~1,5 dia
Kit de componentes. Recriar botões, inputs, selects, checkboxes, switches, badges e scrollbars a partir dos tokens.
Etapa 3~2 dias
Navegação & layout. Migrar o dock de ícones para NavRail lateral; introduzir CommandBar contextual; aplicar a grade de 4px e o respiro nos quatro painéis.
Etapa 4~1,5 dia
Ícones Fluent. Integrar Fluent UI System Icons (SVG/webfont) e substituir todos os glifos e ícones personalizados.
Etapa 5~2 dias
Coleções. Reestilizar listas (biblioteca), TreeView da Bíblia, grid de mídias, tabelas e a faixa de slides; padronizar hover/seleção.
Etapa 6~1,5 dia
Feedback & estados. Toasts, InfoBar, progress, spinner, skeleton, empty/error states, indicadores de conexão e sincronização.
Etapa 7~1 dia
Movimento & responsividade. Transições Fluent, page-transition, expandir/colapsar; verificação em HD/FHD/2K/4K; respeitar prefers-reduced-motion.
Etapa 8~1 dia
Propagação. Aplicar os mesmos tokens ao Servidor e ao Mobile; QA visual e de acessibilidade (foco, contraste, teclado).
Resultado esperado

Ao final, o Lyra terá aparência e qualidade comparáveis a Explorador de Arquivos, Configurações, Visual Studio, PowerToys e Windows Terminal — preservando toda a lógica de negócio. Estimativa total: ~13 dias de trabalho de front-end, entregável por etapas.
